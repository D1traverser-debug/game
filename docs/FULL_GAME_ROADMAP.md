# Production Roadmap — Browser First

All milestones remain NOT_STARTED until evidence and acceptance are attached.

## Phase 0: browser foundation
Static package and manifest; modular TypeScript runtime; simulation/content/render/UI/audio/input/persistence boundaries; same-scene raw WebGL2 vs bundled Three.js comparison; browser/device matrix; asset budgets; WSS protocol/security design.
**Exit:** reproducible package, clean browser launch, renderer decision backed by device measurements, no CDN runtime.

## Phase 1: polished vertical slice
One original hero; one fully dressed realm; three spells and one element interaction; three enemies; one objective; one authored boss; complete movement/combat/XP/upgrade/results loop; production animation/VFX/UI/music/SFX; natural solo victory/defeat; real 2- and 4-client network proof; desktop 60 FPS and mobile 30 FPS targets.
**Exit:** owner and independent review of feel, visual/audio quality, stability, network and performance.

## Phase 2: core systems
Fixed-step simulation, damage/status, spell/augmentation framework, elements/infusions, progression, chests/scrolls, enemy director, boss/objective framework, friendly fire, revive, reconnect and versioned saves.

## Phase 3: full content
Reconcile and implement complete wizard, spell, augmentation, enemy, boss, objective, realm, quest, trial/covenant and meta inventories. Every item gets a stable ID, behavior test, original art/audio and provenance.

## Phase 4: UX/accessibility
Lobby/invites, selection, camp, codex, quests, settings, remapping, touch/controller navigation, readable combat options, localization-ready UI and save recovery.

## Phase 5: release
1/2/3/4-player stress, browser compatibility, CPU/GPU/memory/network profiling, accessibility/security, asset/license audit, hosting/monitoring/rollback and independent full-run playtests.

Do not mass-produce placeholder heroes or maps before the vertical slice passes.
